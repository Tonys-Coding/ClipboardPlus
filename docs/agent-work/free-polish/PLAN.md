# Clipboard+ free polish — v1.8.0

Baseline: clean `0a0e91c` / v1.7.1. User requested roadmap items 1, 2, 3, 4, 7, 8, and 10, implemented sequentially. Root owns architecture, acceptance, and authorized GitHub publication. One Flash worker owns implementation and verification, proceeding in the numbered order below without overlapping feature implementation.

## Contracts and sequence

1. **Keyboard access:** declare `_execute_action` with suggested Alt+Shift+C (all platforms), user-customizable through Chrome's shortcut settings. Focus search on popup open. ArrowDown from search enters the visible favorites-then-recent list; Up/Down navigate rows without stealing editing/caret keys in textareas or dialogs; Enter copies/opens snippet filling. Preserve normal Tab access to controls. Keep focused row visible and handle filtered/deleted results safely. Never conflict with native Control+Shift+V.
2. **Undo deletion:** after a successful individual deletion show an 8-second actionable Undo notice; bulk clearing remains confirmed and irreversible. Worker owns an expiring last-delete tombstone in `chrome.storage.session` (trusted contexts by default), returns an opaque token, and serializes restoration with existing mutations. Restore original ID/timestamps/favorite/metadata without replacing whole state or overwriting newer captures/edits. Repeated deletes replace the previous undo opportunity; expired/used tokens are rejected. Existing equivalent content merges favorite preservation without duplicate IDs/content. Bulk clears invalidate undo. No change to persisted schema v2; popup close may dismiss Undo. Do not restore an expired record outside retention; return clear feedback if limits/retention prevent restoration. Only trusted extension UI senders can invoke restoration.
3. **Full preview:** add Preview to clip actions; read-only scrollable dialog with all text, preserved whitespace, type/source details, and Copy. Keep row click copying and source/content hierarchy. Copy uses the existing snippet workflow when applicable; plain code is readable without remote libraries or fetching. No automatic opening of URLs.
4. **Copy original:** action copies exact stored content through existing clipboard-write handling, bypassing snippet fields and transformations; make available for snippet clips in row menu and preview. Stored content must remain unchanged.
5. **Capture feedback (roadmap 7):** separate off, missing permission, excluded, restricted, checking/loading, paused, and unavailable states; prioritize restrictions accurately for Chrome Web Store and browser pages. Provide appropriate actions (open Capture Controls; retry listener check; resume). Recheck on settings/permission changes and timed-pause expiry, with a readable end time. Do not grant permissions automatically or falsely mark restricted/excluded tabs active after Resume. Surface initial-load failures with Retry instead of endless loading; actionable clipboard failure feedback. Keep content out of diagnostics.
6. **Accessibility (roadmap 8):** shared dialog behavior for edit, preview, snippets, transformations: initial focus, focus trap, Escape, focus restoration, background inertness as appropriate. Menu: arrow keys, Home/End, Escape, focus return, one menu open at a time. Announce ordinary and original copy success with a polite live region. Keep visible focus, non-color cues, accessible concise labels, and honor reduced motion. Verify keyboard sequences in real Chromium.
7. **About & Help (roadmap 10):** small settings section with runtime manifest version, release notes, support, current shortcut and shortcut configuration link/instructions. User-triggered Copy troubleshooting details includes an explicit allowlist only: product/version/build profile, capture enabled/paused/consent-current booleans, website-access status and script-registration health if available. Exclude clip text/counts, source titles/URLs, browsing URLs, excluded domains, IDs, raw errors, account/device identifiers. Clipboard export only, no network send. Useful success/failure feedback. Help explains browser-only shortcut and capture limits.

## Scope and design constraints

- All seven items remain free. Preserve Satoshi, compact flat dark/gold interface, native companion behavior, privacy/consent controls, local-only processing, and existing stored clips.
- No implementation of roadmap 5, 6, or 9 (site exclusion shortcut, search enhancements, storage warnings); no billing, backup, analytics, backend, new website permissions, or native changes.
- Keep centralized serialized service-worker mutations. New session undo protocol is extension-internal and validates expiration/token/source; content scripts must not gain access to undo data. Error recovery must not relax consent or optional permissions.
- Use existing dependencies and test conventions. Increase menu sizing/placement handling for added actions so clipping/overlap regression does not recur.
- v1.8.0 is an additive free polish release. Update package/lock/manifest, README, changelog, relevant support/reviewer docs and store descriptions accurately. Preserve Google verification HTML. Root publishes after acceptance under user's standing instruction; worker does not commit/push/release/submit to Chrome.
