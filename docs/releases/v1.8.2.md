# Clipboard+ v1.8.2 — Steadier local capture

This patch keeps the development extension and the store package from stepping on each other,
and makes local companion capture dependable when no Clipboard+ window is open:

- The Chrome Web Store profile builds into `dist-store`, so `npm run build:store` and its
  validation, packaging, asset, and end-to-end scripts no longer overwrite the development `dist`
  folder that is loaded as the unpacked extension.
- The development profile imports queued macOS companion captures in the background on
  service-worker startup and on a one-minute alarm, so new copies reach history even when the
  popup and Settings page are closed.
- Every companion sync — startup, alarm, popup, and Settings — runs through one serialized queue,
  so overlapping triggers import each capture once and never acknowledge a capture before its
  storage write succeeds. A failed sync retries on the next trigger.
- The public Chrome Web Store permission profile is unchanged: no Native Messaging, no companion
  UI, and no native host calls survive tree-shaking in the store bundle.

All existing Clipboard+ functionality remains free and local. No new permissions, accounts,
analytics, billing, or remote services were added, and the intentional public store profile keeps
no companion bridge until a signed consumer installer is available.

Upload `clipboard-plus-v1.8.2-store.zip` to the existing Chrome Web Store listing. Publishing this
GitHub release does not submit the package to the Chrome Web Store automatically.
